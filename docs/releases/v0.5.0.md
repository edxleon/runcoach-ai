runcoach-ai is now **Runspector**: same project, same data, a name of its own. "RUNCOACH" is a registered trademark of a running-coaching company, and about ten other products share the old name. Runspector is on PyPI now, so installing no longer goes through a git URL.

```bash
uv tool install runspector
runspector serve
```

**Coming from runcoach-ai**

First stop the old app: quit `runcoach serve` (Ctrl-C), and close Claude Code or Claude Desktop sessions that use the `runcoach` MCP server, because a running server would keep writing to the old place. Then:
```bash
uv tool uninstall runcoach-ai
uv tool install runspector
```
- Your data moves by itself. On the first start, `~/.runcoach` becomes `~/.runspector`, and the database, the Garmin session, the cards and the proposals go with it. A `runcoach serve` that still runs keeps the move from happening, and the start says so; `runcoach mcp` and a `runcoach sync` job take no lock, which is why they are stopped first.
- **Claude Code:** `claude mcp list` shows where `runcoach` is registered. Remove it there (`claude mcp remove runcoach`, with `-s user` or `-s project` if that is its scope) and add `claude mcp add runspector -- runspector mcp` the same way.
- **Claude Desktop:** in its MCP configuration, change `"command": "runcoach"` to `"runspector"`.
- **A cron job or scheduled task** with `runcoach sync` becomes `runspector sync`. Until then it fails, and the data goes stale.
- The app's `RUNCOACH_*` settings still work for this release, with a warning, and stop working in v0.6. Rename them to `RUNSPECTOR_*` (for example `RUNSPECTOR_HOME`).
- A browser that used the old version stays signed in, a page left open across the upgrade included, and its theme is kept.
- Old links to `github.com/edxleon/runcoach-ai` lead here.
- To go back by hand, rename `~/.runspector` to `~/.runcoach` and `runspector.db` inside it to `runcoach.db`, then reinstall the old version.

**Garmin sign-in from the page**
- The setup has a "Sign in to Garmin" button, and a sync that failed for want of a session shows "Sign in again". Both take your e-mail, password and, if your account asks for one, Garmin's code. Only the session token is kept, exactly as with `runspector login`, and the first sync starts right after.

**Claude**
- Coach cards run on Claude Code with your own sign-in; a Claude plan is enough and no API key is needed. Variables such as `ANTHROPIC_API_KEY`, exported for other work, are still stripped from the card runs, so they never bill a card. Anyone who wants them for the cards sets `RUNSPECTOR_ALLOW_API_KEY=1`.
- The setup check now asks Claude Code in the same environment the cards run in. With a plan and a key exported for other work, it says "signed in with your Claude subscription" instead of pointing at the key. An API key or a cloud provider set up in Claude Code itself is named as what it is: the cards run on it, and are billed there.

**Also**
- The apply and undo paths of the write path have tests for what the first mutation run found: a week where one session goes wrong still writes (and takes back) the others, a swap's undo never puts an entry on twice, and sessions the claim table holds stay out of the card's "put the rest on the watch".
